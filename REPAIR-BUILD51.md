ScreenLink 0.20.14 / build 51

Transport: media segment responses are fetched in 1 MB HTTP ranges. This avoids passing an entire high-bitrate segment through the broadcast extension's 6 MB response budget when the upstream supports Range. The full segment stays in the browser; phone response memory remains bounded. Same-origin checks, byte-range validation, 32 MB total segment cap and authorization remain enforced. Transient network/408/429/5xx errors retry the same request up to six times without destroying decoder, queued PCM/frames or timing. Permanent source/authorization errors remain visible. Repeated health failures show connection status rather than claiming the decoder failed. Last error and fetch retry count remain in playback diagnostics.

Normal website choices: 1080p and 720p only. Other source sizes are accessible only through explicit ?developer=1 mode, which is used by SD fixture tests. HD is selected from actual offered variants; absent HD is reported, not upscaled or silently replaced with SD. Browser audio timing and Maps pipeline remain unchanged.

Background: adds Keep YouTube running · PiP using an actual muted local YouTube AVPlayer preview, no ReplayKit/screen recording, no silent-audio keepalive. Start YouTube-only, choose ScreenLink in YouTube AirPlay, return to ScreenLink, tap Keep YouTube running · PiP and wait for ACTIVE. Only then leave. The timed task is completed after PiP successfully starts. Closing/pausing PiP may allow iOS to suspend the app; a foreground return retains/resumes the receiver. iOS can still interrupt either runtime mode. PiP/AirPlay coexistence requires a physical iPhone test; it is not established by compilation or browser CI. The old 30-minute task remains a bounded bootstrap/fallback and is not advertised as guaranteed.

Widget: Check Home Screen widget reports whether a WidgetKit extension survived signing and whether its bundle identifier matches the signed app prefix; asks WidgetCenter to reload. This does not prove provisioning/signature validity. If missing, the signed IPA is needed to identify the signing change. Shortcut fallback: Shortcuts → Open URLs → screenlink://start-youtube → Add to Home Screen. No claim that KravaSigner is the confirmed cause.
