3. Complete Specification: docs/screenlink-signaling-contract.md



Below is the complete, unabridged contract for the ScreenLink developer:



# ScreenLink WebRTC Signaling Contract (v2)

Production Base URL: `https://tesla4khmer.com/api/public/screenlink`

Signaling carries only SDP JSON over HTTPS. Media flows iPhone ↔ viewer directly over the local hotspot.
No STUN/TURN is configured: there is no cloud relay fallback, and that does NOT guarantee connectivity.
The existing local ScreenLink viewer token must never be sent to this service.
Signaling expiry or network drops must never instruct either side to close an established local RTCPeerConnection.

---

## 1. Credentials & Authentication

- `deviceSecret`: 32 random bytes (64 hex characters), generated by the server and returned once by `POST /sessions`. Only its SHA-256 hash is stored.
  - Header: `Authorization: Device <deviceSecret>`
- `viewerSecret`: 32 random bytes (64 hex characters), generated by the server and returned by `POST /join`.
  - Header: `Authorization: Viewer <viewerSecret>`
  - **Provisional Status:** Until the iPhone approves the pairing request, the viewer secret can only call `GET /join/{joinId}/status` and `DELETE /join/{joinId}`. Any other call returns `403 not_approved`.
- `pairingCode`: 6 numeric digits (e.g., `346107`). Used for discovery only; never grants session access by itself.
- Secrets are role-scoped: a `Device` secret cannot call viewer routes, and a `Viewer` secret can only access its own `joinId`.

---

## 2. Limits & Lifetimes

- **Rate Limits:**
  - `POST /sessions`: 10 requests / IP / hour.
  - `POST /join`: 5 requests / IP / 10 min and 20 requests / pairing code / 10 min.
  - Exceeding returns `429 rate_limited`.
- **Session Expiry:**
  - Unpaired (`waiting_for_viewer` / `pending_approval`): 180 seconds.
  - Approved / active: 120 seconds of inactivity. Extended automatically on every authenticated heartbeat (`/state`), offer, or answer.
  - Expired sessions return `410 expired`.
- **ICE Gathering (Non-trickle):**
  - Gather up to 3 seconds, then submit full SDP with `iceGathering: "complete"` or `"timeout"`.
  - SDP without an `a=candidate:` line is rejected with `422 no_usable_candidates`.
- **negotiationRevision:**
  - Monotonic counter starting at 1. Every offer, answer, restart, and state call carries this number. Stale requests return `409 stale_revision`.

---

## 3. Broadcaster Endpoints (iPhone)

### 3.1 Create Session
`POST /sessions`
- **Auth:** None
- **Request Body:**
```json
{
  "sdpOffer": "v=0\r\no=- ...\r\na=candidate:1 1 UDP ...\r\n",
  "iceGathering": "complete"
}





Response 201 Created:




{
  "sessionId": "e6f79c3c-80e1-426c-9a3d-cc53cb228776",
  "pairingCode": "346107",
  "deviceSecret": "[64-HEX-DEVICE-SECRET]",
  "negotiationRevision": 1,
  "expiresAt": "2026-11-02T12:29:26.055Z"
}



3.2 Poll Join Requests



GET /sessions/{sessionId}/join-requests





Auth: Authorization: Device <deviceSecret>


Response 200 OK:




{
  "status": "pending_approval",
  "requests": [
    { "joinId": "8f2a1b94-399b-4b10-8f92-c1724d9e0114" }
  ]
}



3.3 Approve Viewer



POST /sessions/{sessionId}/approve





Auth: Authorization: Device <deviceSecret>


Request Body:




{
  "joinId": "8f2a1b94-399b-4b10-8f92-c1724d9e0114"
}





Response 200 OK:




{
  "status": "approved"
}



3.4 Reject Viewer



POST /sessions/{sessionId}/reject





Auth: Authorization: Device <deviceSecret>


Request Body:




{
  "joinId": "8f2a1b94-399b-4b10-8f92-c1724d9e0114"
}





Response 200 OK:




{
  "status": "rejected"
}




(Frees the session slot so another pairing code attempt can be made.)



3.5 Fetch Viewer Answer



GET /sessions/{sessionId}/answer





Auth: Authorization: Device <deviceSecret>


Response 204 No Content: Viewer has not submitted an answer for current revision yet.


Response 200 OK:




{
  "sdpAnswer": "v=0\r\no=- ...\r\na=candidate:1 1 UDP ...\r\n",
  "negotiationRevision": 1
}



3.6 Submit ICE Restart / Renegotiation Offer



POST /sessions/{sessionId}/offer





Auth: Authorization: Device <deviceSecret>


Request Body:




{
  "sdpOffer": "v=0\r\no=- ...\r\na=candidate:2 1 UDP ...\r\n",
  "iceGathering": "complete",
  "negotiationRevision": 2
}





Response 200 OK:




{
  "negotiationRevision": 2
}




(Must increment negotiationRevision by exactly 1. Resets the stored answer and clears any pending restart requests.)



3.7 Heartbeat & State (Broadcaster)



POST /sessions/{sessionId}/state





Auth: Authorization: Device <deviceSecret>


Request Body:




{
  "state": "heartbeat",
  "negotiationRevision": 1,
  "connectionState": "connected",
  "selectedPair": {
    "local": "172.20.10.1:50000",
    "remote": "172.20.10.4:51234",
    "protocol": "udp"
  },
  "bytesSent": 1048576,
  "bytesReceived": 12400
}




(Note: To submit state: "connected", bytesSent must be greater than 0, otherwise 422 connected_requires_outbound_traffic is returned.)





Response 200 OK:




{
  "status": "approved",
  "restartRequestedRevision": null,
  "viewerState": "heartbeat"
}




(If restartRequestedRevision matches the current revision, the iPhone must generate a new ICE restart offer and call POST /sessions/{id}/offer.)



3.8 Close Session



DELETE /sessions/{sessionId}





Auth: Authorization: Device <deviceSecret>


Response 200 OK:




{
  "status": "closed"
}





4. Viewer Endpoints (Tesla Browser)


4.1 Join by Pairing Code



POST /join





Auth: None


Request Body:




{
  "pairingCode": "346107"
}





Response 202 Accepted:




{
  "joinId": "8f2a1b94-399b-4b10-8f92-c1724d9e0114",
  "viewerSecret": "[64-HEX-VIEWER-SECRET]",
  "status": "pending_approval",
  "provisional": true
}




(Errors: 404 unknown, 409 viewer_taken, 410 expired, 429 rate_limited)



4.2 Poll Approval Status



GET /join/{joinId}/status





Auth: Authorization: Viewer <viewerSecret> (Provisional allowed)


Response 200 OK:




{
  "status": "pending_approval",
  "negotiationRevision": null
}




(Once approved, status becomes "approved" and negotiationRevision is 1.)



4.3 Fetch Broadcaster Offer



GET /join/{joinId}/offer





Auth: Authorization: Viewer <viewerSecret> (Approved only)


Response 200 OK:




{
  "sdpOffer": "v=0\r\no=- ...\r\na=candidate:1 1 UDP ...\r\n",
  "negotiationRevision": 1,
  "iceGathering": "complete"
}



4.4 Submit Answer



POST /join/{joinId}/answer





Auth: Authorization: Viewer <viewerSecret> (Approved only)


Request Body:




{
  "sdpAnswer": "v=0\r\no=- ...\r\na=candidate:1 1 UDP ...\r\n",
  "negotiationRevision": 1,
  "iceGathering": "complete"
}





Response 200 OK:




{
  "status": "answer_submitted",
  "negotiationRevision": 1
}



4.5 Request ICE Restart



POST /join/{joinId}/restart





Auth: Authorization: Viewer <viewerSecret> (Approved only)


Request Body:




{
  "negotiationRevision": 1
}





Response 202 Accepted:




{
  "status": "restart_requested",
  "awaitRevision": 2
}



4.6 Heartbeat & State (Viewer)



POST /join/{joinId}/state





Auth: Authorization: Viewer <viewerSecret> (Approved only)


Request Body:




{
  "state": "heartbeat",
  "negotiationRevision": 1,
  "connectionState": "connected",
  "selectedPair": {
    "local": "172.20.10.4:51234",
    "remote": "172.20.10.1:50000",
    "protocol": "udp"
  },
  "bytesReceived": 1048576,
  "framesRendered": 120,
  "dataChannelPingOk": true
}




(Note: To submit state: "connected", bytesReceived must be > 0 and either framesRendered > 0 or dataChannelPingOk: true must be true. When both device and viewer report verified connected, the session status transitions to connected.)





Response 200 OK:




{
  "status": "connected",
  "negotiationRevision": 1
}



4.7 Leave Session



DELETE /join/{joinId}





Auth: Authorization: Viewer <viewerSecret>


Response 200 OK:




{
  "status": "closed"
}





5. Development Roadmap




Milestone 1 (Immediate Scope):



Broadcaster creates session via POST /sessions and displays 6-digit code.


Viewer enters pairing code at POST /join.


iPhone receives prompt and calls POST .../approve.


SDP offer/answer exchange completes.


Broadcaster and viewer open an RTCDataChannel ("ping") and verify bidirectional messaging (dataChannelPingOk: true).






Milestone 2 (Media Streaming):



Broadcaster attaches native H.264 video tracks for iPhone Maps screen and YouTube AirPlay.


Viewer receives streams, renders to <canvas>, and engages Hide/Show source controls.
