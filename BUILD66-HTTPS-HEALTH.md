# ScreenLink 0.20.29 / build66

User authorized automatic HTTPS health/recovery to address the possible first-loss path, while explicitly preserving build64's smooth playback. This does not establish that a dead HTTPS listener caused the original physical failure.

Receiver starts a serial utility-queue monitor when a valid personalized HTTPS identity is available. Every 15s (first check after5s), it makes a real pinned-certificate TLS1.2+ request to loopback443 with Host/SNI car.tesla4khmer.com and a random32hex challenge. Response must be HTTP200 and echo that challenge. Total network deadline2s. Certificate validity, hostname, exact bundled leaf and TLS verification stay enabled. Health endpoint accepts only local-loopback HTTPS GET with empty body and valid challenge; exposes no media/auth/status. Two reserved loopback HTTPS slots separate probes from the12 existing request slots.

Two consecutive failures are required before rebind. A real external HTTPS response in the last20s suppresses repair; one transient timeout doesn't rebind. Minimum60s between repairs. Replacement identity is validated before retiring the owned listener. Generation/listener-serial leases prevent stale probes, stop cancellation or foreground recovery from rebinding a replacement listener. Only443 is rebound; HTTP8080, receiver generation, viewer approval, MediaCast, AirPlay, current media, PiP and VPN remain intact. Foreground resumes an immediate serial check; stop cancels monitor. iOS suspension can pause the monitor; it does not grant background execution.

CanvasPlayer/CanvasScreen/MediaCast/BoundedDownload/YouTubePiP/LocalVPN/PacketTunnelProvider/widget source unchanged from build65 (and smooth build64). UI scripting changes are build labels only. No recording, quality, decoder, buffering or audio-scheduler changes. Existing build65 credential/cache/approval fixes retained. Original63/64/65 and ScreenLink3333 remain saved separately.

Tests include real encrypted challenge responses, one-byte fragmentation, wrong certificate/status/nonce, bounded handshake/read stalls and pure recovery policy. A generated Foundation harness extracts exact production startListener, checkHTTPSHealth and repairHTTPSListener methods; redirects only test port and identity directory; injects HTTPS response stalls while HTTP is healthy; checks repeat-failure rebind, unchanged HTTP/media/approval/PiP/VPN/generation, positive-traffic suppression, cooldown, stale leases and stop cancellation. Existing browser recovery and actual video/audio regressions still required. Only cloud Mac compilation; trusted identity restored privately after download.
